# K230 视觉测量系统 README

## 1. 项目简介

本项目基于亚博智能 K230 / CanMV 平台，实现一个面向电赛题目的视觉测量系统。

系统目标是对放置在摄像头轴线上的饮料杯、瓶子或透明容器进行视觉检测，并测量、显示以下信息：

- `D`：目标物到摄像头或装置参考位置的距离；
- `H`：目标物实际高度；
- `L`：液面高度或液体高度；
- `bottom pixel`：目标物最下方点在图像中的像素坐标；
- `level line`：液面线位置；
- `target box`：目标物融合后的完整外接框。

当前代码已经实现了一个触摸屏 UI 系统，包含两个工作模式：

1. **Dynamic Detect：动态检测模式**
2. **Fixed 3s Measure：固定目标 3 秒采样测量模式**

系统目前使用 YOLOv8 segmentation 模型进行目标粗检测，然后通过“轴线碎片融合 + 多帧滤波 + 固定时间采样”提高测量稳定性。

---

## 2. 题目背景与需求理解

题目基本要求为：

1. 从三个饮料杯中随机取出一个，摆放在轴线上的固定位置，一键启动装置，测量并显示 `D` 和 `H`。
2. 从剩余目标物中继续随机取出一个，摆放在轴线上的固定位置，一键启动测量并显示 `D` 和 `H`。
3. 对最后一个目标物重复测量。
4. 发挥部分可能要求在 50 cm 到 100 cm 范围内测量 `D`、`H`、`L`。

因此，本项目具有几个非常重要的先验条件：

- 每次测量时，视野中原则上只有一个主要目标物；
- 目标物摆放在摄像头轴线附近；
- 目标物可能是透明杯、透明瓶、带液体的饮料杯；
- 透明物体检测容易受到反光、折射、背景干扰影响；
- 单帧检测结果不一定可靠，需要多帧融合。

## 3. 总体实现思路

本项目采用如下技术路线：

```text
摄像头采集图像
        ↓
K230 上运行 YOLOv8 segmentation kmodel
        ↓
检测 bottle / cup 相关目标框
        ↓
利用“目标在轴线上”的题目约束
        ↓
对中轴线附近的 bottle / cup 碎片框进行融合
        ↓
得到完整目标外接框
        ↓
提取目标底部像素点 bottom_y
        ↓
通过 D-bottom_y 标定关系估计距离 D
        ↓
利用目标图像高度 hpix 和相机参数估计实际高度 H
        ↓
在目标 ROI 内进行液面检测
        ↓
计算液体高度 L
        ↓
在 LCD / 触摸屏 UI 上显示结果

核心思想是：

不完全依赖 YOLO 单帧识别结果，而是结合题目物理约束、空间融合和时间滤波，让测量结果更稳定。

4. 为什么需要“轴线碎片融合”

透明瓶和透明杯在视觉上有一个典型问题：YOLO 经常把一个完整目标识别成多个碎片。

常见情况：

完整透明瓶
    ↓
YOLO 检测结果：
上半部分：bottle，低置信度，甚至漏检
下半部分：cup，高置信度

原因是：

空瓶上半部分透明，边缘弱；
液体部分有明显颜色、边缘和折射特征；
液体区域很像一个杯子；
反光会让边缘断裂；
背景复杂时透明区域与背景混在一起。

因此，如果只选置信度最高的框，很容易选中“下半截 cup”，导致：

目标框高度偏小；
bottom pixel 不稳定；
H 计算错误；
液面 ROI 错位；
L 计算不准。

所以当前代码使用了“中轴线碎片融合”策略：

检测所有 bottle / cup 碎片
        ↓
只保留靠近画面中轴线的碎片
        ↓
过滤太小、太宽、太扁的异常框
        ↓
选取主碎片
        ↓
合并与主碎片横向重叠的相关碎片
        ↓
取所有碎片的外接矩形
        ↓
得到完整目标框

这样可以把透明瓶被 YOLO 分裂成的 bottle + cup 框重新融合成一个完整物理目标。

5. 当前代码结构说明

当前代码主要由以下几个类组成。

5.1 TouchReader：触摸屏读取模块

TouchReader 用于读取 K230 触摸屏点击坐标。

当前修正版的关键点是：

points = self.tp.read(1)
pt = points[0]
x = int(pt.x)
y = int(pt.y)
event = int(pt.event)

也就是说，K230 的 TOUCH.read(1) 返回的是一个触摸点列表或元组，真正的触摸点对象是 points[0]。

TouchReader 还提供了 coord_mode 坐标修正功能：

self.coord_mode = 0

可选值：

coord_mode	含义
0	坐标不变
1	左右翻转
2	上下翻转
3	左右和上下都翻转
4	x / y 交换
5	x / y 交换后左右翻转
6	x / y 交换后上下翻转
7	x / y 交换后左右和上下都翻转

如果触摸有响应但按钮点不准，就只需要修改 coord_mode。

5.2 UIButton：按钮模块

UIButton 是简单的 UI 按钮类，包含：

按钮位置；
按钮尺寸；
按钮文字；
点击区域判断；
绘制按钮。

主要方法：

hit(px, py)
draw(osd)

其中 hit() 用于判断触摸点是否落在按钮内部。

5.3 SegmentationApp：核心视觉测量模块

SegmentationApp 是整个项目的核心类，继承自 AIBase。

它主要负责：

配置 YOLO 输入预处理；
执行 YOLO segmentation 后处理；
进行 bottle / cup 目标融合；
计算 D / H / L；
检测液面；
动态模式下做目标保持和平滑；
固定模式下做 3 秒采样、筛点和结果锁定。
6. YOLO 推理与后处理

当前代码使用：

kmodel_path = "/sdcard/kmodel/yolov8n_seg_320.kmodel"
model_input_size = [320, 320]
confidence_threshold = 0.10
nms_threshold = 0.45
mask_threshold = 0.45
rgb888p_size = [320, 320]
display_size = [640, 480]

其中：

yolov8n_seg_320.kmodel 是当前使用的 YOLOv8 segmentation 模型；
输入尺寸为 320 × 320；
显示尺寸为 640 × 480；
目标类别来自 COCO 数据集，其中：
bottle 对应类别索引 39；
cup 对应类别索引 41。

当前模型是通用 COCO 模型，并不是专门针对比赛目标物训练的模型。

7. 目标检测与轴线融合逻辑

当前代码核心函数：

get_merged_axis_target(dets, ids, scores)

它做了以下事情：

7.1 只保留 bottle / cup
if class_id not in [39, 41]:
    continue

因为比赛目标主要是杯子、瓶子或饮料容器。

7.2 降低置信度阈值
if score < 0.08:
    continue

透明杯和透明瓶的置信度可能偏低，因此不宜使用太高阈值。

7.3 轴线约束
axis_x = self.display_size[0] // 2
axis_error = abs(cx - axis_x)

if axis_error > 130:
    continue

题目要求目标物放在轴线上，因此只保留靠近画面中轴线的检测框。

7.4 过滤异常框

代码会过滤：

面积太小的框；
太宽的框；
太扁的框；
不在轴线附近的框。

这样可以减少背景误检。

7.5 合并碎片框

对符合条件的 bottle / cup 框取最外接矩形：

min_x = 所有碎片最小 x
min_y = 所有碎片最小 y
max_x = 所有碎片最大 x
max_y = 所有碎片最大 y

最终得到：

merged_box = [min_x, min_y, merged_w, merged_h]

这个框被认为是完整目标框。

8. D、H、L 的当前计算方式
8.1 当前 D 的计算方式

当前代码里使用的是占位二次公式：

D = self.D_a * bottom_y * bottom_y + self.D_b * bottom_y + self.D_c

当前参数为：

self.D_a = 0.0
self.D_b = -0.20
self.D_c = 120.0

这只是临时公式，还不是最终标定公式。

当前实际思路是：

目标物底部像素 bottom_y
        ↓
查表 / 插值
        ↓
得到真实距离 D

下一步需要建立 bottom_y → D 的标定表。

8.2 当前 H 的计算方式

当前代码中高度估计方式为：

H = D * hpix / fy_pixel

其中：

D 是估计距离；
hpix 是目标外接框的像素高度；
fy_pixel 是等效焦距，当前暂设为：
self.fy_pixel = 420.0

这个值目前也是临时值，后续应使用真实相机内参中的 fy 替代，或者根据实际分辨率缩放后的 fy 替代。

8.3 当前 L 的计算方式

液体高度计算方式为：

lpix = bottom_y - level_y
L = H * lpix / hpix

含义：

目标实际高度 H 对应图像高度 hpix
液体像素高度 lpix 对应实际液体高度 L

这是一个基于相似比例的估算方法。

9. 液面检测逻辑

当前液面检测函数为：

detect_liquid_from_ndarray(img, x1, y1, w, h)

基本流程：

输入融合后的目标框 x1, y1, w, h
        ↓
取目标中间区域作为 ROI
        ↓
在 ROI 中选多列垂直扫描线
        ↓
对每一列计算亮度和颜色变化特征
        ↓
寻找纵向梯度突变点
        ↓
对多列候选液面点进行水平投票
        ↓
得到最终液面 y 坐标

ROI 当前设置为：

roi_x = x1 + int(w * 0.22)
roi_y = y1 + int(h * 0.18)
roi_w = int(w * 0.56)
roi_h = int(h * 0.68)

这样做的目的是避开瓶壁、杯壁、瓶口、瓶底和桌面，只在目标中间区域寻找液面。

当前液面检测使用：

多列扫描；
亮度特征；
色差特征；
3 点平滑；
梯度峰值；
水平一致性投票；
中值滤波。

12. 当前存在的问题
12.1 液面有时不准确

当前液面检测主要依赖 ROI 内的亮度和颜色梯度。实际场景中液面不准的原因包括：

透明液体本身颜色变化弱；
水的液面边缘不明显；
杯壁反光形成假液面；
背景线条透过杯体形成假梯度；
桌面反光干扰；
ROI 位置依赖目标框，如果框不准，液面检测也会偏；
空杯或浅色液体时，液面几乎不可见；
镜头自动曝光变化会导致亮度梯度波动。

当前液面算法已经使用多列投票和中值滤波，但仍不能完全解决透明液体和强反光问题。

12.2 有些杯子检测不到，尤其是透明杯

当前模型是通用 COCO 模型，不是专门针对比赛目标物训练的模型。透明杯、空杯、远距离杯子容易漏检，原因包括：

透明杯边缘弱；
远距离时目标像素太小；
320 × 320 输入分辨率会压缩小目标；
背景复杂时透明杯与背景混合；
COCO 模型对比赛目标物外观不一定适配；
空杯没有明显颜色和纹理；
杯口、杯底、液面可能被识别成分离碎片；
某些透明杯可能没有被 YOLO 输出任何 bottle / cup 框。

当前通过降低阈值、轴线融合、短时保持可以缓解，但无法完全根治。

12.3 D、H 目前还没有真实标定

当前 D 使用的是临时二次公式：

D = a * bottom_y^2 + b * bottom_y + c

这只是占位，实际比赛必须通过标定数据替换。

当前 H 使用的 fy_pixel = 420.0 也只是临时值，后续需要用真实相机内参和畸变校正后计算。

12.4 目标框仍可能受误检影响

虽然当前使用了轴线融合，但如果背景中有与 cup / bottle 相似的物体，并且恰好靠近轴线，仍可能被合并进目标框。

解决方向：

加强背景控制；
增加目标尺寸范围约束；
增加固定位置 ROI 限制；
使用专用模型；
使用传统视觉边缘进行二次验证。
13. 现场使用建议

为了提高识别稳定性，建议比赛现场这样布置：

摄像头固定，不要手持；
目标物放在固定轴线上；
背后放纯色背景板或黑白竖条背景板；
避免强光正对杯壁；
避免桌面强反光；
目标物尽量位于画面中心；
杯底不要被遮挡；
每次正式测量使用 Fixed 3s Measure 模式；
Dynamic Detect 只用于调试和观察。
14. 下一步计划

下一步主要分为四个方向：

14.1 建立 bottom_y 与 D 的标定关系

当前代码中 D 仍然是占位公式。下一步需要实测建立：

目标底部像素 bottom_y  →  实际距离 D

建议标定流程：

固定 K230 摄像头位置和角度；
在轴线上设置多个已知距离点，例如：
50 cm
60 cm
70 cm
80 cm
90 cm
100 cm
每个距离点放置目标物；
记录固定测量模式输出的 bottom_y；
每个距离采集多次，取中位数；
得到标定表：
D / cm	bottom_y / pixel
50	y1
60	y2
70	y3
80	y4
90	y5
100	y6
使用分段线性插值或多项式拟合替换当前临时公式。

推荐优先使用分段线性插值，因为稳定、可解释、不会在标定区间外剧烈发散。

14.2 使用相机内参和畸变系数

用户提供的亚博智能 K230 原装 GC2093 摄像头在 1280 × 960 下的内参为：

camera_matrix = [
    1199.1495245491617, 0.0, 670.4213222250077,
    0.0, 1200.6879329729338, 475.11122810359876,
    0.0, 0.0, 1.0
]

dist_coeffs = [
    -0.0331624688297151,
    0.04145795463721313,
    0.0016964134879770974,
    0.0008834973490863845,
    -0.05414957483933673
]

其中：

fx = 1199.1495
fy = 1200.6879
cx = 670.4213
cy = 475.1112

因为当前程序显示和模型处理不是 1280 × 960，而是：

rgb888p_size = [320, 320]
display_size = [640, 480]

所以内参不能直接照搬，必须按实际图像尺寸进行缩放。

如果从 1280 × 960 缩放到 640 × 480，缩放比例为：

scale_x = 640 / 1280 = 0.5
scale_y = 480 / 960 = 0.5

则对应 640 × 480 下的内参约为：

fx_640 = 1199.1495245491617 * 0.5
fy_480 = 1200.6879329729338 * 0.5
cx_640 = 670.4213222250077 * 0.5
cy_480 = 475.11122810359876 * 0.5

即：

fx_640 = 599.5747622745809
fy_480 = 600.3439664864669
cx_640 = 335.21066111250385
cy_480 = 237.55561405179938

后续可以将：

self.fy_pixel = 420.0

替换为更合理的：

self.fy_pixel = 600.3439664864669

前提是当前目标框高度确实对应 640 × 480 显示坐标。

14.3 使用畸变校正提高 bottom_y 和 H 的稳定性

当前代码没有进行畸变校正。实际镜头存在径向畸变和切向畸变，尤其在画面边缘会影响像素坐标。

下一步可加入：

原始图像
    ↓
畸变校正
    ↓
YOLO 检测 / 目标框融合
    ↓
bottom_y、hpix、level_y 计算

但是在 K230 实时运行时，完整图像去畸变可能开销较大。可以先采用折中方案：

目标固定在中轴线附近；
只在标定阶段考虑畸变影响；
bottom_y → D 用实测插值直接吸收畸变误差；
后续再考虑 ROI 局部坐标校正。

对于比赛项目，优先级建议是：

先做 bottom_y-D 实测插值
再做 H 的相机内参修正
最后再做完整畸变校正
14.4 优化透明杯 / 透明瓶检测

后续需要重点解决透明杯漏检问题。

推荐路线：

方案 A：继续优化当前通用模型后处理

可以继续调：

confidence_threshold = 0.08
nms_threshold = 0.45
mask_threshold = 0.35

并加强：

轴线约束；
固定位置 ROI；
框尺寸约束；
目标保持；
固定模式多帧采样。

优点：不需要重新训练。

缺点：透明杯完全没有检测框时无能为力。

方案 B：训练专用 target 模型

建议最终训练一个只识别比赛目标物的模型。

类别不要分 bottle / cup，建议统一为：

target

原因：

题目只需要测 D、H、L；
不要求真正区分 bottle 和 cup；
统一类别能减少 bottle / cup 误分类；
对透明杯、透明瓶更容易学稳定外接框。

采集数据建议：

条件	建议
距离	50、60、70、80、90、100 cm
状态	空杯、透明水、有色液体、不透明液体
光照	正常光、侧光、弱光、强反光
背景	比赛现场背景、纯色背景、条纹背景
数量	至少 500 张，最好 1000 到 2000 张

标注方式：

标完整目标外接框，不要只标液体区域。
从杯口/瓶盖最高点到杯底最低点。
左右包含完整杯壁或瓶身边界。

模型建议：

YOLOv8n detect 320
或 YOLOv8n detect 416

如果 100 cm 距离目标太小，建议尝试 416 × 416 输入，但推理速度会降低。

15.2 替换 H 计算函数

当前：

H = D * hpix / self.fy_pixel

后续建议使用缩放后的相机内参：

self.fy_pixel = 600.3439664864669

然后：

H = D * hpix / fy

该公式建立在小孔成像模型上：

图像高度 / 焦距 = 实际高度 / 距离

即：

H = D × hpix / fy
15.3 液面检测优化方向

液面优化可以从以下方向做：

固定模式下对 level_y 也做 3 秒采样中位数；
加入液面候选点置信度；
对空杯和透明水单独判断；
加入水平线检测，而不是只看纵向梯度；
使用 Canny / Sobel 只在 ROI 内找水平边缘；
对 ROI 做背景差分；
给目标背后放一块黑白条纹背景，增强透明液体折射边界；
对强反光区域做过滤；
液面检测失败时允许人工或规则兜底，例如显示 L:None。
